# 管理员入门

简体中文 | [English](ADMIN.en.md) · [安装与模型配置](DEPLOYMENT.md)

用安装向导创建的管理员账号登录。自行注册的账号是普通玩家，不会显示管理入口；酒馆成员身份也不等于平台管理员。

## 第一次开放酒馆

1. 打开右上角 **管理后台**，在 **开放新酒馆** 中填写对外名称和访问标识。名称可以用中文；访问标识使用小写字母、数字和连字符，例如 `abyss-tavern`。
2. 游戏包选择 **深渊酒馆**。希望朋友登录后就能看到它，勾选 **公开展示**；希望他们直接加入，再勾选 **允许玩家自由加入**，然后点击 **开放酒馆**。
3. 返回首页进入酒馆。第一次进入会初始化游戏数据，需要稍等。私人酒馆可让朋友先注册，再在平台管理页的 **分配成员** 中加入。
4. 用普通玩家账号确认首页能找到酒馆、能加入并打开游戏。没有勾选公开展示、也没有分配成员的酒馆，不会出现在普通玩家首页。

不同酒馆独立保存角色、物品和剧情。平台管理页负责酒馆入口、成员、账号启停和游戏进程；进入酒馆后的 **管理** 栏目负责该酒馆的玩法配置。

## 让第一批玩家入驻

新酒馆没有冒险者是正常的。玩家进入 **我的** 提交角色预约，管理员进入 **建筑 → 预约管理**，查看等待中的预约与可用床位，再填写数量、点击 **执行抽取**。抽取成功的玩家才能获得冒险者；没有空床时先处理宿舍容量。

预约管理中可以设置 **宿舍完工后自动抽取**、**每天 20:00 自动抽取**。每日抽取时间按北京时间；是否启用由你的酒馆安排决定。不要把新酒馆暂无角色误认为安装失败。

## 配置模型与运行节奏

用管理员账号进入目标酒馆，打开 **管理 → 探险 → 运行与 AI → S1 AI 模型配置**。

1. 在模型预设中填写名称、厂商协议、API 接口地址、模型名称和 API Key。可以添加多个预设。
2. 在 **AI 用途分配** 中，为剧情、大纲、审核、建筑、申诉等用途选择预设与思考强度；也可搜索用途后批量分配。
3. 点击 **保存模型与用途配置**。新配置供后续请求立即使用，不需要停服、重启或运行命令。已经开始的请求继续使用开始时的配置。

Key 只写不可读：已有 Key 留空保持，勾选清空才删除。需要备用线路时展开 **备用线路与备用 Key**，选择完整备用预设或添加同线路备用凭证。

配置独立保存在当前酒馆的数据库中，其他酒馆不会一起改变，重启后仍保留。尚未独立保存的酒馆显示安装时的初始配置。多人编辑时，过期版本会被拒绝，请刷新后重新核对。

同一面板下方可打开 **AI 用量统计与失败详情**；凭证因余额不足暂停后，充值完成可点击 **充值后恢复调用**。恢复按钮本身不会发起 AI 请求。

中文剧情正文唯一推荐 **`deepseek-v4-pro-0423`**。根据本项目测试经验，后续新版本的中文剧情效果较差，建议固定这个版本。

进入酒馆的 **管理 → 探险 → 运行与 AI**，可以调整组队人数、发车间隔、每日探险配额和快慢时段，并保存设置。界面中的时间按北京时间。新开服可以先沿用默认值，熟悉实际节奏后再调整。

**管理台顶部的 AI 总闸** 用于控制新的 AI 请求；**运行与 AI** 中也可以配置停用时段。暂停 AI 不等于停止整个平台，也不代表已发出的模型请求立即取消。维护前应等待正在进行的剧情与结算结束。

## 常用管理入口

| 要做什么 | 入口 |
| --- | --- |
| 修改公开展示、自由加入、成员资格 | 平台 **管理后台** |
| 发布通知、管理等级上限 | 酒馆 **管理 → 运营** |
| 查看匹配与调度、调整运行节奏 | 酒馆 **管理 → 探险** |
| 查看玩家数据申诉 | 酒馆 **管理 → 审核 → 数据申诉** |
| 查看或编辑建筑、角色预约、转盘和物品图鉴 | 酒馆 **建筑** 中的管理员卡片，或 **管理 → 建筑图鉴** |

这些入口只对管理员显示。修改前确认进入的是目标酒馆；多酒馆部署时尤其注意名称。

## 开服前确认

- 用普通玩家账号走通加入酒馆、提交预约和获得冒险者的步骤。
- 确认模型配置有效、AI 总闸和调度设置符合你的开放安排。真正生成剧情会消耗服务商额度。
- 给朋友使用可访问的服务器地址；`127.0.0.1` 只适合本机。公网部署、停机备份与恢复按 [部署教程](DEPLOYMENT.md) 操作。

## AI 输入压缩开关

在目标酒馆的 **管理 → 探险 → 运行与 AI → S1 AI 模型配置** 中，可以一键切换 **资产描述压缩与特质分类筛选**。默认关闭，仅影响当前酒馆，重启后保留。

- **关闭**：相关特质、技能和装备描述按原文发送，避免压缩或分类筛选造成的信息遗漏。但上下文更长，模型可能遗忘细节、分散注意力，Token 消耗与费用也会增加。
- **开启**：使用审核通过的摘要与特质场景筛选，减少输入长度和 Token 开销，但存在信息遗漏风险；生成摘要与分类本身也会调用 AI。

装备、归档和资产依赖等游戏生效规则保持不变。设置供后续生成的输入使用；已冻结的探险输入及配套审核保持一致，已发出的请求不会立即取消。关闭后不再新建后台资产压缩任务，也不会把旧摘要用于新的输入。
