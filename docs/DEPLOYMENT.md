# 安装、部署与维护

简体中文 | [English](DEPLOYMENT.en.md)

## 第一次安装：跟着向导完成

先安装 **Python 3.12+** 和 **Node.js 22.12+ 或 24 LTS**（包含 npm）。Windows 安装 Python 时勾选加入 PATH，安装完成后重新打开终端。Linux 若提示缺少 `venv`，请通过所用发行版的包管理器安装对应的 Python venv 组件。

从 GitHub 的 **Code → Download ZIP** 下载源码并完整解压；也可以用 Git 克隆仓库。不要在 ZIP 内直接运行脚本。

**Windows：双击项目里的 `tools/setup.cmd`。** 也可以在项目目录打开终端：

```powershell
python tools/setup.py
```

**Linux：在项目目录运行：**

```bash
python3 tools/setup.py
```

向导会依次安装依赖、构建网页、生成本地配置、询问模型信息、创建首个管理员并启动游戏。首次下载可能需要几分钟；安装失败会停止，按提示处理后可以重新运行。脚本会检查环境，不会替你安装系统级 Python、Node.js 或修改防火墙。

### 接口地址、Key 和模型分别填什么？

**中文剧情正文生成唯一推荐使用 `deepseek-v4-pro-0423`。** 根据本项目的实际测试经验，后续新版本在中文剧情正文上的效果较差，建议固定使用该版本，不要自动替换为最新版。

准备一组服务商提供的 **OpenAI Chat Completions 兼容接口**信息；仅有聊天网站账号或网页订阅，不代表已有 API 使用权限。

| 向导询问 | 应当填写 | 注意 |
| --- | --- | --- |
| 接口基础地址 | 服务商文档里的 API Base URL | 示意为 `https://your-provider.example/v1`，请填写你实际使用的地址；不是聊天网页地址。若粘贴了末尾 `/chat/completions`，向导会自动去掉它。 |
| 模型 ID | 服务商模型列表中准确的模型标识 | 复制 API 使用的 ID，不要填写网页显示的别名；是否带组织名前缀、是否带版本号，以该服务商为准。 |
| API Key | 在该服务商控制台创建的密钥 | 输入时不显示字符，粘贴后按回车即可。不要填登录密码，也不要额外加 `Bearer `。 |

上面的 `.example` 地址只是格式示意，不能用来运行游戏。模型需要支持对话和结构化 JSON 输出，并有足够的上下文长度；不同模型的剧情质量、速度和费用会不同。向导只保存配置，不发送测试生成请求，实际游玩才会使用模型服务。

配置保存在本机 `.env`，Key 不会显示在完成提示或写入命令参数。再次运行时，已有完整模型配置默认保留；回答 `y` 才会进入修改。修改已有模型时，留空表示保留原值。高级多模型用户的其它模型和用途分配也会保留。

### 创建管理员并进入酒馆

具体开服步骤、角色预约与抽取、游戏内管理入口见 [管理员入门](ADMIN.md)。

向导会让你设置管理员用户名和密码。用户名使用 3–32 位英文字母、数字或下划线；密码为 6–64 位，隐藏输入并确认两次。已有可用管理员时自动跳过，不会重置密码或覆盖已有账号。

看到启动提示后，浏览器打开 **http://127.0.0.1:5500**，用刚创建的管理员登录，在平台管理页创建酒馆并进入。邀请其他玩家时，可在创建酒馆时选择是否公开显示、是否允许自行加入，或由管理员分配成员。

启动窗口需要保持运行。停止时按 **Ctrl+C**，等待进程退出后再关闭窗口。

## 以后启动或更换模型

**正常启动不需要重新安装：** Windows 双击 `tools/start.cmd`；Linux 在项目目录运行 `python3 tools/start.py`。

**更换 Key、模型或接口地址：** 用管理员账号进入目标酒馆，在 **管理 → 探险 → 运行与 AI → S1 AI 模型配置** 中填写并保存。可以建立多个模型预设，并按用途分配。保存仅影响当前酒馆，后续请求立即生效，无需重启。Key 留空保留，只有明确勾选清空才删除。完整步骤见 [管理员入门](ADMIN.md)。

安装向导中的 `.env` 模型设置是新酒馆的初始默认值。网页保存的独立设置保存在该酒馆数据库中，备份时应一并保留数据库。

安装中断、依赖已装好时，可用 `.venv` 中的 Python 运行 `tools/setup.py --configure-only` 继续配置。添加 `--no-start` 可以完成配置后暂不启动。需要把配置放在其它私有目录时，可使用 `--env-file <路径>`；之后启动时使用相同参数，或统一设置 `PLATFORM_ENV_FILE`。

## 常见问题

| 现象 | 处理方式 |
| --- | --- |
| 找不到 Python、Node.js 或 npm | 安装要求的版本、确认加入 PATH，然后重新打开终端。 |
| 下载依赖失败 | 检查网络，处理终端中报错的依赖下载步骤，再运行安装向导。 |
| 模型返回 401/403 | 检查 Key 是否属于这个接口服务、是否有效，以及模型权限和账户状态。 |
| 模型不存在或接口 404 | 核对模型 ID 和 API 基础地址；不要把聊天网页或完整请求路径当作基础地址。 |
| 页面打不开 | 确认启动窗口仍在运行、网页构建成功、端口未被其它程序占用，并查看启动输出中的地址。 |
| 修改模型后仍使用旧设置 | 正常停止整个平台并重新启动；确认修改的是启动时使用的同一份配置。 |
| 朋友打不开我的 `127.0.0.1` 地址 | 这个地址只指向访问者自己的电脑。多人远程访问请按下面的公网入口说明配置域名和 HTTPS。 |

## 配置文件

向导会生成独立随机密钥并写入本机 `.env`，再次执行会保留有效配置。正常重启不会更换密钥。

`PLATFORM_ENV_FILE` 可指定项目外的私有配置文件。配置和备份应放在仅部署账号可访问的位置，不要提交到 Git 或放进网页静态目录。

## 公网入口

`backend/serve.py` 同时服务构建后的前端和 `/api`，默认监听 `127.0.0.1:5500`。Runtime 端口也应只监听本机，不对公网开放。把 `deploy/Caddyfile.example` 中的域名改为实际域名，配置 DNS、开放 HTTPS 端口并用 Caddy 反向代理；示例等待时间覆盖最长导出请求。不要通过 Vite 开发服务或 Flask 开发服务器提供公网服务。

Linux 可按 `deploy/ai-rpg.service.example` 配置独立服务账号、路径与私有配置。必须保留 `KillMode=control-group`，确保异常退出时所属子进程被清理。Windows 手动运行时用 Ctrl+C 正常停止；强制结束进程之后先核对各酒馆运行状态再维护。生产入口会对 Runtime 数据目录加独占锁，防止另一个入口或维护工具同时操作。

默认 SQLite 便于本地预览。自定义 SQLite URL 请使用绝对文件路径，避免 Flask 与维护命令的相对路径解析差异。长期运行建议为控制面及每个酒馆分别建立 PostgreSQL 数据库，设置 `DATABASE_URL` 与 `RUNTIME_DATABASE_URL_TEMPLATE`。模板支持 `{runtime_id}`、`{runtime_key}`（去掉连字符）、`{tavern_id}`、`{slug}`、`{pack_id}`。不要让不同酒馆模板展开到同一个库。数据库须提前创建；平台只创建/升级表结构。

## 备份与恢复

1. 停止接收新请求，等待正在运行的剧情/结算结束；在管理页停止酒馆，再正常停止平台服务。
2. 使用服务相同的 `PLATFORM_ENV_FILE` 与 `.venv` Python 执行：

   ```powershell
   .\.venv\Scripts\python.exe tools/backup.py backup D:\private-backups\before-upgrade
   ```

3. 另行安全保存私有配置、当前发布源码以及自定义的外部文件。数据库备份目录不包含 `.env`，包含账号、成员资格、各酒馆数据库、来源版本和 SHA-256 清单；它属于私密玩家数据，不能公开。
4. 在新的空目录/空数据库中配置恢复目标，再执行 `tools/backup.py restore <备份目录>`。SQLite 目标文件必须不存在；PostgreSQL 目标库必须预先创建且为空。数据库类型不能在恢复时改变。恢复前验证所有文件校验值和所有目标，拒绝覆盖已有 SQLite 文件或有表的 PostgreSQL 库。
5. 使用备份时的代码版本启动恢复实例，核对账号、酒馆成员和各酒馆数据，再开放入口。恢复失败时保持服务停止；删除本次新建的目标或换新的空目标后重试，不要在半恢复状态上启动。

PostgreSQL 使用 `pg_dump`/`pg_restore`，安装与服务器兼容的客户端并加入 PATH，或设置 `PG_BIN` 指向其 `bin` 目录。密码经子进程环境传递，不写入命令参数或备份清单。备份开始时要求所有酒馆停止，避免跨数据库备份时间不一致；若数据库记录仍保留 PID，先确认孤儿进程状态，通过平台正常停止后重试，不能只删除锁文件绕过检查。

## 升级与回滚

当前控制面使用建表启动方式，游戏包有各自迁移逻辑；没有通用自动降级器。升级必须先做上述停机备份，并在恢复副本上用目标版本启动、跑回归测试和检查业务数据。保留旧代码、旧配置与同一时间点备份。回滚时停止新版本，恢复整套旧数据库并切回对应旧代码；不要让旧代码直接连接已升级数据库。
